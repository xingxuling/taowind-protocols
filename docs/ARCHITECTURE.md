# 层级与职责

## 总仓库的权限

这个仓库维护发现、导航、版本锁定和状态说明。它不是新执行引擎，不从其他Owner夺取语义权威。修改目录不能自动修订OPP、TINP、RCL或RNCS/RFE的规范。

## 名称容易混淆的地方

- P00–P15是16个路线图能力域，不是16个已发布且兼容性冻结的wire protocol
- OPP是协议族，也有对应参考运行时。核心协议版本与工具链版本必须分开：目前分别是`0.1.0-candidate.1`和`0.3.0-candidate.1`
- TINP仓库承载当前网络套件候选和适配实现；它引用的`twni`局部Profile不能自动提升为整个新互联网的通用规格
- `opp.session.v0.1`组合能力描述、受限适配与会话契约，不是第七个OPP核心协议
- RCL拥有其语言与执行判据；TINP调用固定程序。引用RNCS/RFE世界ID不代表实现世界权威、租约转换或数据同步

## OPP六个核心协议

| 协议 | 作用 | 不能据此推出 |
|---|---|---|
| RXP | 定义跨系统交换信封的语义载荷 | 信封本身会执行动作 |
| RCP | 描述能力、输入输出、约束和副作用 | 声明能力就具有权限或实时可用 |
| RAP | 描述可识别、可版本化工件及依赖 | 所有工件都已能安装/运行 |
| REP | 将主张与来源、方法、复现和边界关联 | 一条引用即为独立验证 |
| RSP | 区分观察、推导、预测等状态并追踪版本 | 预测可被当成已发生事实 |
| CHP | 协商版本、能力与范围，并达成协议或拒绝 | 协商结果可自动扩张权限 |

权威定义：[OPP Specification](https://github.com/xingxuling/OPP/blob/da65ab1d26c01c5e2939294e415b9fd07b7dbe5a/docs/SPECIFICATION.md)、[OPP Registry](https://github.com/xingxuling/OPP/blob/da65ab1d26c01c5e2939294e415b9fd07b7dbe5a/registry/protocols.json)。

## 一次组合调用的边界

OPP判断双方是否兼容，形成具体契约和有限桥接方案。TINP的受控执行入口独立检查主体、会话、权限和路线；准入失败不执行业务。结果返回后核对签名及请求绑定。离线验收既有OPP回执仅是证据处理，不等于重新调用Provider，也不产生权限。

P04主要复用OPP CHP/RCP，但OPP的REP/RSP/RAP等语义不能被P04这个标签完整包住；映射是多对多的导航关系。P05/P06/P09中的运行时增强也不能证明P12应用种子或P14网络隔离已实现。
